# Учебный планер

## Идея проекта

- Учебный планер — это веб-приложение, в котором студент может хранить учебные задачи и следить за их выполнением.
- Главная сущность проекта — задача с названием, описанием, дедлайном и статусом.
- Пользователь может создавать, просматривать, редактировать и удалять задачи, менять их статус и фильтровать список.
- Приложение предназначено для студентов, которым нужно собирать задания и сроки в одном месте, чтобы ничего не забывать.
- Мне интересен этот проект, потому что он решает знакомую учебную проблему и позволяет на практике собрать полноценное приложение с API, базой данных и интерфейсом.

## Первая версия

- Полный CRUD для учебных задач: создание, просмотр, редактирование и удаление.
- Дедлайн и один из трёх статусов: запланирована, в работе или готово.
- Фильтрация списка по статусу; сохранение данных в SQLite.
- Один пользователь без регистрации и авторизации — так проще сосредоточиться на API и основной логике проекта.

## Запуск локально

Нужен Python 3.12.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload
```

Откройте [http://localhost:8000](http://localhost:8000). API-документация Swagger доступна на [http://localhost:8000/docs](http://localhost:8000/docs). По умолчанию база создаётся в `data/tasks.db`; переменная окружения `DATABASE_PATH` позволяет выбрать другой файл.

## Запуск через Docker

```powershell
docker compose up --build
```

Откройте [http://localhost:8000](http://localhost:8000). База хранится в именованном Docker volume и сохраняется после перезапуска контейнера.

## ORM-модели и тестовые данные

`app/models.py` описывает таблицы `users` и `tasks`, связь через внешний ключ `tasks.user_id` и каскадное удаление задач вместе с пользователем. Учебная база для проверки схемы создаётся отдельно от базы запущенного API.

```powershell
python -m pip install -r requirements.txt
python seed.py
```

Скрипт создаёт `project.db` рядом с `seed.py`, добавляет 3 пользователей и 12 задач, затем сохраняет их через `commit()`. Если база уже содержит записи, скрипт откажется их перезаписывать. При необходимости путь можно изменить переменной окружения `DATABASE_URL`.

Снимок базы в DB Browser: [Browse Data — project.db](docs/project-db-browser.png).

## API

Все ответы и запросы — JSON. Поля задачи:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | Идентификатор, назначается сервером |
| `title` | string | Название, от 1 до 200 символов |
| `description` | string | Описание, до 2000 символов |
| `due_date` | `YYYY-MM-DD` или `null` | Дедлайн |
| `status` | string | `planned`, `in_progress` или `done` |
| `created_at`, `updated_at` | datetime | Время создания и последнего изменения в UTC |

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/tasks` | Список задач; необязательный фильтр `?status=planned` |
| `POST` | `/api/tasks` | Создать задачу |
| `GET` | `/api/tasks/{id}` | Получить задачу |
| `PUT` | `/api/tasks/{id}` | Полностью заменить поля задачи |
| `PATCH` | `/api/tasks/{id}` | Изменить переданные поля |
| `DELETE` | `/api/tasks/{id}` | Удалить задачу, ответ `204` |

Для ручной проверки CRUD в Postman импортируйте `postman/study-planner-crud.postman_collection.json`, запустите сервер и выполните коллекцию на `http://localhost:8000`. Postman-тесты проверяют ответы и состояние ресурса после создания, замены и удаления.

Пример создания:

```json
{
  "title": "Подготовить доклад",
  "description": "Найти источники и сделать слайды",
  "due_date": "2026-11-01",
  "status": "planned"
}
```

Неизвестная задача возвращает `404`, некорректные данные — `422`. Приложение рассчитано на одного пользователя и пока не включает регистрацию и авторизацию.
